# InteFlow 全新官网 · 落地页方案

> 依据 `landing-page-design` skill 的 Output format 产出。展示页：`design-demos/landing-page-demo.html`
> 仓库：https://github.com/JasonSun2009CN/InteFlow

## 0. 假设（原方案未提供，先定下来）

| 项 | 取值 |
|---|---|
| 唯一转化动作 | 下载安装包 |
| 受众 | 自学者 + 带班老师（备考 SAT / GRE / 学科题） |
| 流量来源 | GitHub、搜索引擎「SAT 错题整理」「PDF 题库导入」、学习社群 |
| 核心异议 | ① 是不是又要充值 API ② 我的题会不会被上传 ③ 非 SAT 能用吗 |
| 品牌语气 | 克制、具体、不喊口号 |
| 设计方向 | 暖白纸感 + 单一荧光绿强调色，无背景渐变 |

## 1. 页面顺序（Page outline）

1. Hero：徽章 + 主标题 + 副标题 + 单一 CTA + 一行可验证的能力声明 + 产品界面截图
2. **标语揭示段（B11 强制）**：三行大字，逐词点亮
3. 四个收益卡（2×2）
4. 三步流程
5. 能力边界：会做 / 不会做
6. FAQ（7 条，其中 3 条直接打核心异议）
7. 结尾 CTA（与首屏完全一致）
8. Footer：隐私 / 条款 / MIT / 数据位置

## 2. Hero 文案

- **标题**：把题库文档拖进来，在你自己电脑上刷完一套
- **副标题**：InteFlow 在本地把 PDF、Word、Markdown 拆成结构化题目，还原分栏、题号、选项和答案键，然后给你一个考试风格的全屏练习界面，和一间逐题复盘的工坊。
- **主 CTA**：下载 InteFlow（次说明：免费 · MIT 开源 · macOS 与 Windows）
- **证明行**：MIT 开源 · 304 个测试通过 · 解析与判分全程本地，只有你点「AI 讲解」时才出网。
  （这三个说法都能在仓库里直接核对，测试数建议上线时从 CI badge 读取，不要写死。）
- **徽章**：0 token 解析，数据不出这台电脑

## 3. 收益（Benefits，四条）

1. **导入不烧 token** — 本地确定性解析，整条链路没有一次模型调用。数字：`0`
2. **像在考场里一样做完** — 全屏、正/倒计时、自动交卷、键盘作答。数字：`A 到 Z`
3. **复盘不是对答案** — 左题面右分析，自动保存，生词拖进词表，解析导出 PDF。数字：`2 到 5 分屏`
4. **数据留在 data 目录** — 单文件 SQLite，无上传链路，删目录即彻底删除。数字：`100% 本地`

## 4. 三步流程

1. 把文件拖进来（60 MB 上限，逐页报告，可取消）
2. 把答案补上（A 到 Z 网格 / 粘贴 `1 A 2 C 3 AC`）
3. 做完，然后逐题写（交卷看分板块得分，写解析，导出 PDF / DOCX）

## 5. 标语揭示段（B11）

> 题目在本地拆开，分数在本地算出，**连 AI 讲解**都要你亲手点一下。

- 字号 `text-4xl` 到 `text-5xl`，最大宽度 880px
- 逐词从 30% 不透明度升到 100%，按阅读顺序划过触发线，非整块翻转

## 6. FAQ（7 条）

1. 一定要联网或者付 API 费用吗？
2. 我的题目和解析会被上传吗？
3. 支持哪些文件？扫描件能用吗？
4. 不是 SAT 的题也能用吗？
5. AI 讲解默认是开着的吗？
6. Windows 能用吗？怎么更新？
7. 安装包里有版权题目吗？

## 7. SEO / AEO

- **可索引**：`index, follow`（长期品牌页，不是投放页）
- **title**：InteFlow · 把题库文档变成一套能复盘的练习
- **meta description**：InteFlow 在本地把 PDF、Word、Markdown 解析成结构化题目，提供考试风格的全屏练习和逐题复盘工作区。解析与判分都在你自己的电脑上完成。
- **结构化数据**：`SoftwareApplication`（含 `offers.price = 0`）+ `FAQPage`
- **内链**：功能页、下载页、FAQ 从首页各链一次

## 8. 布局选择

**Type A：经典 Hero + 分段**。理由：产品价值必须靠界面截图在一屏内说清，长文叙事（B）会拖慢下载型转化，极简页（C）只适合高意图流量，对比页（D）留给 SEO 子页。

## 9. 视觉规则落点（Part B）

| 规则 | 实现 |
|---|---|
| 字体 | Geist 单一字族，数字与代码用 Geist Mono；中文回落 PingFang SC |
| 字阶 | 只用 Tailwind 默认梯级（12/14/16/18/20/24/30/36/48/60） |
| 间距 | 只用 0/2/4/8/12/16/24/32/40/48/64/80/96 |
| 圆角 | 外卡 16px，内嵌块与 8px 间距配合取 8px（16−8） |
| 背景 | 白天暖纸 `#FAF8F3`；黑夜暖黑 `#131209`（skill 允许色）；不使用纯黑 |
| 渐变 | 只出现在 Hero 标题文字上（白天 `#000 → #666`，黑夜 `#FFF → #9B9B9B`） |
| 纹理 | Hero 顶部 1px 点阵，用蒙版渐隐；属于纹理不是背景渐变，可整段删除 |
| 图标 | Phosphor 风格的线性图标（展示页里手绘 SVG，生产环境换 Phosphor） |
| 动效 | 统一 `cubic-bezier(0.22,1,0.36,1)`；只动 transform 与 opacity；滚动揭示用 IntersectionObserver 且只播一次 |
| 导航 | 悬浮胶囊、半透明 + 背景模糊、菜单开合图标变形、移动端全高面板逐条 60ms 入场 |
| 无障碍 | skip link、可见 focus ring、`prefers-reduced-motion` 降级为纯透明度变化 |

## 9.1 双主题（day / night）

默认 **白天**（`data-theme="light"`），不跟随系统，避免讨厌暗色的用户第一眼看到黑底。
右上角太阳 / 月亮按钮切换，图标用旋转 + 缩放过渡，不硬切；选择写入 `localStorage['if-theme']`，刷新后保持。

| Token | 白天 | 黑夜 |
|---|---|---|
| `--bg` | `#FAF8F3` 暖纸 | `#131209` 暖黑 |
| `--surface` | `#FFFFFF` | `#1F1F1F` |
| `--surface-2` | `#F3F1EA` | `#272727` |
| `--surface-3` | `#E9E6DC` | `#313131` |
| `--line` | `#E2DFD5` | `#313131` |
| `--ink` | `#0D0D0C` | `#FFFFFF` |
| `--accent`（填充） | `#CDF25B` | `#CDF25B` |
| `--accent-text`（文字 / 数字） | `#4F6B10` 橄榄绿 | `#CDF25B` |
| `--btn-bg` | `#111110`（黑按钮） | `#CDF25B`（绿按钮） |
| `--hero-grad` | `#000 → #666` | `#FFF → #9B9B9B` |

关键点：荧光绿在暖白底上做文字对比度不够，所以白天只把绿色用在**填充**（选项高亮、进度点、按钮 hover），
所有绿色文字换成橄榄绿 `#4F6B10`（对 `#FAF8F3` 对比度约 5.2:1），黑夜则直接用荧光绿。
主按钮两个主题反过来：白天是近黑实心按钮，黑夜是荧光绿按钮，保证各自都是最高对比。

## 10. 文案纪律

- 不用连字符、不用斜体、不加 900 字重
- 不用 revolutionise / supercharge / 世界级 这类填充词
- **不编造用户证言、客户名、统计数字**。没有真实数据就不写，用「能力边界」两列替代证言位
- 只允许出现仓库里可验证的事实：MIT 许可、pytest 用例数、19 家模型服务商、data 目录结构、60 MB 上限
- 界面稿里的 `42:17`、`13 / 54` 属于产品截图内容，不是业绩数字，可以保留
- 版本号、发布日期在拿到真实 release 之前不要写
