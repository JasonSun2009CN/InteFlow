01 / POSITION

Let's start with the boundaries.

InteFlow is not a study assistant that can chat about anything. It gets the certain things right first, then puts optional AI behind a key you explicitly press.

RULE 01 0 TOKEN

The LLM is not on the main path.

Import, parsing, grading, review and export are deterministic local computation by default; AI appears only as an explicit action, or as a fallback you have switched on.

  • PDF / DOCX / Markdown convert locally by default, 0 tokens
  • AI recognition fallback: only when you enable it and deterministic parsing fails
  • AI explanations / connectivity test / optional word-exam grading (explicit)
  • If the switch is off, there's no key, or a call fails, it falls back to local and says so

One path that works end to end, with no account required.

RULE 02 LOCAL FIRST

Your data stays on this computer by default.

Question banks, answers, analysis and vocabulary all live under the repo's data/: one SQLite file, plus each paper's doc.ifmd.md and images. Nothing is uploaded to the cloud by default; when you use AI, only the current question context is sent to the provider you configured.

  • No accounts, no cloud sync
  • Backup = copy the data/ folder
  • Delete data/ to start from scratch
  • The dictionary index and exported files stay local too

Offline, everything works as usual — except the optional AI.

“A study tool should still work on a plane.”

No network? Import, practise, grade, review and export all still work.

02 / WORKFLOW

Five steps, from file to notes.

No hidden sync step, and no workbench that has to be online. Every step can stop on its own — change what you need, then carry on.

  1. 01

    Import a question bank

    CAPTURE

    Drag in PDF, DOCX, .md or .ifmd.md. PyMuPDF handles two-column layouts, question numbers, options, answer-table write-back and image extraction; scanned pages go through OCR automatically. Suspicious pages stop at the review stage so you can choose Commit or Cancel.

    • ≤ 60 MB
    • Page-by-page report
    • macOS Vision / Tesseract
    • No options → fill-in
    0 TOKEN

    Deterministic conversion

  2. 02

    Complete the answer key

    ANSWER KEY

    Papers missing answers go to the answer-entry page: click letters question by question, select several options, add multiple accepted answers for fill-ins, or paste 1-A 2-C, ACBDA, 3-AC directly. Preview before saving; saving writes the answers back to the source file.

    • Letter grid
    • Bulk paste
    • Multiple accepted answers
    • Validation + preview
    WRITE-BACK

    Syncs doc.ifmd.md

  3. 03

    Practise in full screen

    PRACTICE

    On the start screen choose a count-up or countdown timer (it remembers your last mm:ss), then enter the exam-style full-screen view. Jump with the question panel, flag with Mark for review, drive it from the keyboard with A–D and ← →, and answer both multiple-select and fill-in questions.

    • Countdown
    • Keyboard
    • Question panel
    • Submit confirmation
    0 TOKEN

    Answers never leave the backend before submission

  4. 04

    Review question by question

    CORE

    The full-screen review workbench puts the question, analysis, AI Tutor and vocabulary into a 2-of-4 split view. Read the question and correct answer on the left, and write your analysis in a Pages-style editor on the right with autosave every 0.9 seconds; drag a word into the vocabulary list to build vocabulary straight from context.

    • All / Wrong / Correct
    • Markdown + KaTeX
    • Drag words in
    • Notebook preview
    WORKSPACE

    Layout and split ratios are remembered

  5. 05

    Distil and export

    OUTPUT

    Mistakes automatically gathers the questions still wrong on your latest attempt; Starred keeps the ones you flag by hand; Sessions records every submission. One review notebook per paper, exporting only the questions with written analysis; word lists export to xlsx, and word-exam results can become a QR code.

    • Mistakes + Starred
    • Sessions
    • PDF / DOCX / MD
    • xlsx · QR
    PORTABLE

    Files stay in data/exports/

07 / QUESTIONS

Still have questions?

Here are the answers to the things people trip over first. More detailed specs, the data model and format documentation all live in the repo docs.

Ask on GitHub ↗
01Does it only support SAT?

No. A question's sec is a free-form label (rw, math, physics, history…), not a fixed enum. Any bank made of "question number + two or more options" can be imported; items where no options are detected are treated as fill-ins. The built-in SAT bank is just an out-of-the-box example.

02Do I need to be online or configure an API key?

No. Import, parsing, grading, review, vocabulary and export don't depend on a network. Only AI explanations, connectivity tests, and word-exam AI grading that you turn on yourself call an external model, sending the current question / answer context to the provider you configured; with no key or a failed call it falls back to local and tells you.

03Where is my data stored?

All under the repo's data/: app.db holds structured data, docs/<id>/doc.ifmd.md holds the original questions and answers, assets/ holds images, and exports land in exports/. To back up, copy the whole directory; to reset, delete it (the backend rebuilds it).

04Which system dependencies do I need?

Running the basics only needs Python 3.11+ and Node.js 18+; the one-click script creates .venv and installs the frontend and backend dependencies. PDF export additionally needs pango / cairo / gdk-pixbuf / harfbuzz; scanned-page OCR can optionally use the system tesseract, and macOS can also use Vision; math export can add a MathJax bridge. When something is missing, only that feature degrades or warns — it won't take the rest down with it.

05Can I use my own dictionary?

Yes. My dictionary in Settings supports manual edits and imports from CSV / TSV / JSON / TXT, and takes priority over Merriam-Webster. For English-to-English Merriam-Webster definitions, put an Eudic .eudb into dictionary/ and the index is built automatically on first lookup. Copyrighted dictionary files are not distributed with the repo.

06Why doesn't the practice page follow the theme?

It's deliberate. Practising needs the least visual distraction and stable contrast, so the full-screen practice page stays outside .app-theme and uses a neutral slate / blue; the review workbench follows the theme you chose. A theme only changes the visual language, never the question layout or the interactions.

07What does the exported notebook contain?

One review notebook per paper: a cover with the user name and score, then every question with written analysis in question order (stem, figures, your analysis). Markdown / DOCX / PDF, downloaded straight from the browser with a copy left in data/exports/. Whole-paper PDF / DOCX is exported from the Library instead.

08Is the app interface in Chinese?

The app interface is in English, with buttons and page names matching the README; the documentation comes in both Chinese and English. Question content isn't limited by language — mixed Chinese/English papers can be imported and practised alike. This site is available in both languages so that first-time visitors can grasp the whole path faster.

09Can I customize the wrong-answer analysis template?

Yes. Write a Markdown template under Settings → Analysis template and empty wrong-answer analysis pages are filled in automatically; existing analysis is never overwritten. The template is only an initial draft — it isn't saved until you change it, and autosave only starts once you begin writing, so a blank question is never miscounted as "analysis written" and pulled into an export.
